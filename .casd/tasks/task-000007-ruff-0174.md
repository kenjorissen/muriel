# Ruff 0.17.4

Goal: [goal-000002](../goals/goal-000002-staged-dependency-upgrades.md)

## Objective

Upgrade development-only Ruff from 0.16.3 to 0.17.4 while retaining the existing lint/format policy and non-mutating verification commands, without changing application behavior.

## Contracts and owning evidence

- `docs/design.md` section 26.3: Ruff is the single formatter, import sorter and linter, pinned in development requirements, usable in ordinary and Cassidy worktrees without network access during deterministic checks.
- `README.md`, Development checks, and root `AGENTS.md`: use the shared main virtualenv and existing `scripts/format`, `scripts/quality-check`, and `scripts/check` owners; these own mutating formatting versus non-mutating verification.
- Owners: `requirements-dev.txt`, `pyproject.toml`, `scripts/format`, `scripts/quality-check`, `scripts/check`. Current policy targets py314, line length 100, preview=false, and E4/E7/E9/F/B/UP/I/RUF with the narrow Django-generated migration RUF012 exception.
- Target is the Ruff portion of Dependabot PR #2 as captured at `bfb734df6079ecb45b51591eee96ed744d2737a6`, not its application upgrades. Review official intervening release notes where they affect selected rules/formatting, including https://github.com/astral-sh/ruff/releases/tag/0.17.0 and https://github.com/astral-sh/ruff/releases/tag/0.17.4 .

## Acceptance

1. The declared development requirements pin Ruff 0.17.4; install it in the shared main virtualenv for worker and subsequent authoritative Check. Keep runtime requirements unchanged and retain tblib/pip-audit.
2. Existing non-preview lint selections, formatting policy and narrowly justified framework exception remain intact. Do not silence new errors through blanket ignores, disabling rules, broad exclusions or modifying frozen planning history.
3. Any source changes are the minimum behavior-preserving fixes or formatting required by the accepted policy under the new release. Classify new findings before changing code: an intentional product rule is not to be altered merely for lint success. Escalate a consequential behavior/compatibility decision instead of expanding this tooling Task.
4. `scripts/quality-check` and `scripts/check` remain non-mutating/offline and pass under the installed target version. `scripts/format` retains its existing explicit mutating role. No replacement toolchain, pre-commit integration, frontend or dependency framework.

## Verification and boundary

Record the installed Ruff version and apply the existing fixed-purpose helpers. If the release requires formatting changes, demonstrate the final checks leave tracked source unchanged. Existing behavioral tests are the protection for mechanical fixes; do not add tests that only assert a version string. No new runtime behavior is intended. Run quality and complete checks, and preserve the preceding Actions v7 outcome. GitHub exact-revision verification is performed by the authorized coordinator after acceptance, not implied by the local pass.

Worker authority excludes remote pushes, PR disposition, GitHub settings, deployment and data changes. Other PR #2 dependencies remain separate future Tasks. This development-only upgrade does not justify a staging restart or production rollout.
