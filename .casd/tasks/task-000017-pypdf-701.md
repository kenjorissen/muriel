# pypdf 7.0.1

Goal: [goal-000002](../goals/goal-000002-staged-dependency-upgrades.md)

## Objective and boundary

Upgrade pypdf 6.21.4 to 7.0.1 while preserving the PDF reader evidence that protects generated schedule/report artifacts. Run after the accepted framework upgrade in task-000016 in the planned sequence; ReportLab and both text libraries remain at their existing pins for this increment. The parser upgrade is independently useful and its artifact requirements survive the later renderer/text upgrades.

## Contracts, owners and upstream assessment

`requirements.txt` owns the pin. This application's pypdf consumers are tests reading generated PDFs, not an end-user PDF upload/parser service. `schedules/pdf.py` remains the ReportLab presentation owner. Existing direct evidence is in `test_precepting_calendar_pdf.py`, `test_master_schedule_workspace.py`, `test_schedule_reports.py` and `test_stipend_reports.py`: extracted content, metadata, page geometry, text placement, grid association and read-only endpoint behavior.

Preserve `docs/design.md` accepted month-calendar export/last-edit semantics, Master Schedule read-only projections, and sections 25.1/25.2 report scope, provenance, totals, warnings and on-demand artifacts. Preserve the embedded-font provenance in `schedules/fonts/README.md`. Reports remain authenticated and do not initialize/change schedule facts.

Read `https://github.com/py-pdf/pypdf/blob/7.0.1/CHANGELOG.md` and the 7.0.0 deprecation removals. 7.0 includes stricter stream/XFA/image bounds and nondeterministic identifiers; 7.0.1 adds image-buffer sizing security fixes, UTF-8 decoding and text extraction changes. Preserve those security improvements; neither a clean audit nor lack of exposed PDF input establishes exhaustive security assurance.

## Acceptance and verification

1. Declare/install pypdf 7.0.1 with the shared main virtualenv. Preserve other direct pins and document necessary transitive resolution. No introduction of encryption extras, a PDF upload endpoint, parser fallback, compatibility monkeypatch or new rendering engine.
2. All four existing PDF-owning suites pass against real generated artifacts. Retain content/metadata, Unicode names, page orientation, grid/row/column association, bounds, clipping/overflow protections, report totals/provenance and no-mutation guarantees. Trace any changed visitor or extraction semantics through shared test helpers and every consumer, not just the first failing test.
3. If adapting a helper to supported pypdf APIs is necessary, preserve its independent behavioral oracle; do not normalize away wrong associations or missing/clipped content. Use representative faulty artifact evidence where needed to show an adapted assertion still detects its intended failure. Random object IDs/serialization are not product requirements; raw byte equality is not the acceptance criterion. Do not hard-code the new extracted output merely because it differs.
4. `./scripts/quality-check`, `./scripts/check` and `./scripts/security-audit` pass with output inspected for unexpected errors. Exact Candidate Check and independent Review are required. The pin may be the only source change if existing behavioral coverage is sufficient; permanent package-version tests are unnecessary.

## Resources and authority

Python 3.14 and existing SQLite/PostgreSQL support remain unchanged. Use normal Django runners and shared Python. Generated PDFs and scratch outputs belong to the worker; record/remove exact owned scratch on success/failure, retaining useful evidence in the Attempt. No application data, production/staging access, deployment, push, PR disposition, reset, credentials/sudo changes or unrelated cleanup. The coordinator owns GitHub and subsequent grouped non-reset staging verification.

## Execution strategy

Establish the existing PDF test helpers' supported pypdf usage before the pin change. Run focused artifacts before the full suite to distinguish parser-oracle changes from renderer changes; the latter has its own subsequent Task. Add coverage only for a demonstrated gap or a directly necessary adaptation, not a new PDF testing platform.
